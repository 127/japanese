# Правила для агента в этой папке

## Что где лежит

- Корень: готовые листы для печати (`!_*.pdf`, `!_stats.md`), `AGENTS.md`, `CLAUDE.md`.
- `_scans/` — исходные сканы из учебника: `kanji001.jpg`, `kanji002.jpg`, `kanji004.jpg` (таблицы иероглифов), `voc001.jpg` … `voc013.jpg` и `voc008b.jpg` (словари и фразы), `kanji003.png` (хитоцу, футацу … — не из учебника). Новые сканы класть сюда же, в корень не класть.
- `_strokes_src/` — исходники и скрипт для `!_kanji_strokes.pdf`.
- `_kanji_src/` — данные и скрипт для `!_kanji_all_text.pdf`.
- `_voc_src/` — данные и скрипт для `!_kanji_voc_all_text.pdf`.
- Имена: `*_scan.pdf` — версия из сканов, `*_text.pdf` — та же, набранная шрифтом.
- `golovnin_japanese.pdf` — учебник; в репозиторий не входит (см. `.gitignore`), его нужно скачать отдельно и положить в корень.

## !_kanji_voc_all_scan.pdf

Сборник из сканов: словари, фразы и таблицы кандзи уроков 1–6.

Для этого файла важен порядок картинок: они должны идти строго как в учебнике (golovnin_japanese.pdf), кандзи и словари вперемежку по урокам, а не так, как удобнее для заполнения страниц.

Файлы берутся из `_scans/`. Порядок: voc001, voc002, voc003, voc004, voc005, voc006, kanji001, voc007, voc008, kanji002, voc008b, voc009, voc010, kanji004, voc011, voc012, voc013. kanji003 (хитоцу, футацу … — не из учебника) стоит последней. voc008b вырезан из учебника (стр. 71, «Иероглифическое написание введённых ранее слов»).

Менять порядок ради экономии места нельзя, даже если на странице остаётся пустое место. Пустого места при этом стоит избегать другими способами: масштабом картинок и разбивкой по страницам.

## !_kanji_all_scan.pdf

Отдельный файл только из таблиц кандзи (сканы из `_scans/`): kanji001, kanji002, kanji004. kanji003 (хитоцу, футацу …) сюда не входит — это не кандзи.

## !_kanji_all_text.pdf

Те же три таблицы кандзи, что в `!_kanji_all_scan.pdf`, но набранные шрифтом, а не сканом: один лист A4, слева уроки 4 и 5, справа урок 6; строка — иероглиф, он над чертой и кун под чертой, значение, ключ, № ключа; заголовков нет. Чтения он и кун набраны крупно (11,5 pt, шрифт без засечек) — мельче не делать; значение и номер ключа 8,5 pt. Исключение делает сам скрипт: если чтение или значение не помещается в свою строку (налезает на соседнюю или шире своей ячейки), шрифт уменьшается только в этой ячейке — по фактической ширине и высоте текста, не вручную. Так ужаты, например, кун у 生 и 私. Данные — `_kanji_src/kanji_table.py` (перепечатаны со сканов), сборка — `python3 _kanji_src/build_kanji_table.py` из корня. Скан лежит рядом под именем `!_kanji_all_scan.pdf`.

## !_kanji_voc_all_text.pdf

Текстовая версия сборника `!_kanji_voc_all_scan.pdf`: словари, словосочетания, обиходные фразы, собственные имена и таблицы кандзи уроков 1–6, набранные шрифтом. Порядок блоков — строго как в учебнике (тот же, что у скан-версии); в конце — счёт предметов (хитоцу, футацу …), которого в учебнике нет.

Вид: A4, поля 8 pt, две колонки, текст идёт по левой колонке сверху вниз, потом по правой. Строка словаря — слово, чтение каной (если есть), перевод. Над каждым блоком серая подпись «Урок N · что это». Сейчас 3 страницы (скан — 6).

Размер текста: весь текст одного размера — 10,5 pt (русский, кана, чтения, подписи блоков, ключи, номера). Крупнее только сам иероглиф в таблицах кандзи. Мельчить отдельные части (чтения, подписи) нельзя; размер задаётся одной переменной `SIZE` в скрипте.

Данные — `_voc_src/voc_data.py` (перепечатаны со сканов из `_scans/`; таблицы кандзи берутся из `_kanji_src/kanji_table.py`, второй копии нет). Сборка — `python3 _voc_src/build_voc_text.py` из корня.

Чего в текстовой версии нет: в сканах жирным выделены слоги высокого тона — это выделение не перенесено, за тоном смотреть в скан.

## Коммиты

- Автор коммитов — тот, что задан в локальном конфиге этого репозитория (`git config user.name`, `git config user.email`); не менять и не подставлять другой.
- В сообщение коммита не добавлять никаких строк об авторстве ИИ и служебных хвостов: ни `Co-Authored-By`, ни `Generated with …`, ни ссылок на сессию. Только описание изменений.
- Репозиторий публичный: в коммиты и файлы не должны попадать рабочая почта, локальные пути и прочая личная информация.
- Коммитить только по просьбе пользователя.

## Сохранение файлов в эту папку

После каждого сохранения файла в эту папку нужно проверять, что локальная копия совпадает с только что созданной версией (например, по md5), и только потом сообщать, что файл обновлён.

Причина: при записи обновлённого файла под тем же именем сюда уже попадали устаревшие копии, хотя в чате показывалась свежая версия. Если копии не совпали — пересохранить и проверить ещё раз.

Графику порядка черт брать из AnimCJK (см. раздел про !_kanji_strokes.pdf), а не рисовать черты самому.

## !_kanji_strokes.pdf — порядок черт

Что это: пошаговые схемы порядка черт для 50 иероглифов из `!_kanji_all_text.pdf`, в порядке таблиц учебника. Для каждого знака — иероглиф целиком, затем по кадру на черту: ненаписанные черты бледные, написанные серые, новая чёрная, рядом с ней красная стрелка — направление письма.

Откуда графика: единственный источник — AnimCJK, японский набор (https://github.com/parsimonhi/animCJK, папка `svgsJa`, файл `<десятичный код знака>.svg`). В нём есть все дзёё- и дзиммэйё-кандзи, порядок черт японский. Из файла берутся контуры черт и осевые линии (от начала черты к концу); стрелки строит скрипт по осевым линиям.

Как импортировано: файлы скачаны напрямую с GitHub (raw.githubusercontent.com) и лежат без изменений в `_strokes_src/animcjk/`.

Сборка: `python3 _strokes_src/build_strokes.py` из корня репозитория — пишет `!_kanji_strokes.pdf`. Нужен Python с пакетом playwright и его Chromium (`pip install playwright && playwright install chromium`). Чтобы добавить иероглиф, дописать его в строку `K` в скрипте в порядке учебника и запустить скрипт: недостающий файл AnimCJK он скачает сам. Подробности — в комментарии в начале скрипта.

Прошлые реализации (по этому пути больше не идём):
- Сначала схемы рисовались из KanjiVG (github.com/KanjiVG/kanjivg): линии ровной толщины, стрелки и значки направления ставил скрипт — читались плохо.
- Затем 47 знаков брались готовыми картинками с Викисклада (Commons: CJK Stroke Order Project, файлы `字-jbw.png` / `字-bw.png`), а три отсутствующих там знака (戸, 洋, 紙) дорисовывались из KanjiVG скриптом `draw_missing.py`. Минусы: разный стиль картинок, у 14 знаков не японский вариант, растр, снятый с экрана, пропуски в покрытии.
- Последнее состояние этой реализации (спрайт Викисклада, исходники KanjiVG, `sopbuild.py`, `draw_missing.py`) — в коммите `7853f6b`; посмотреть: `git show 7853f6b --stat`, достать файл: `git show 7853f6b:_strokes_src/draw_missing.py`.
- Возвращаться к Викискладу и KanjiVG для этого файла не нужно: источник — только AnimCJK.

Лицензия: SVG-файлы AnimCJK распространяются по Arphic Public License; шапка с лицензией сохранена в каждом файле, удалять её нельзя.

Размеры, которых нужно придерживаться всегда:
- Все иероглифы на всех страницах одного размера: кадр 37,6 pt (около 13 мм).
- Лист A4, поля 8 pt со всех сторон; промежуток между группами в строке 0,45 кадра, между строками 0,22 кадра.
- Сейчас 2 страницы. При добавлении новых иероглифов размер не менять — добавлять страницы.
- Никакого текста на страницах.
